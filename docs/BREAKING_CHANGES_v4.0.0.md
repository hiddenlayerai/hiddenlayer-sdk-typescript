# Breaking API Changes: v3.x → v4.0.0

v4.0.0 is generated by [Fern](https://buildwithfern.com/) from the same OpenAPI specification that generated v3.x with Stainless. The package name, the `HiddenLayer` client, the environment variables, Node 20 support, the CommonJS and ESM builds and the model and community scanners all stay. Every method v3.6.0 had keeps its name and path; what changes is how arguments are passed, the names of the request and response types, the client options, errors and two methods that now paginate. v4.0.0 also adds every API in the specification that v3.x didn't cover.

## Imports

```typescript
// v3.x and v4.0.0: both forms still work
import HiddenLayer from "@hiddenlayerai/hiddenlayer-sdk";
import { HiddenLayer, ModelScanner, CommunityScanner } from "@hiddenlayerai/hiddenlayer-sdk";
```

In CommonJS, `require` no longer returns the client class itself:

```javascript
// v3.x
const HiddenLayer = require("@hiddenlayerai/hiddenlayer-sdk");

// v4.0.0
const { HiddenLayer } = require("@hiddenlayerai/hiddenlayer-sdk");
```

Request and response types move from namespaces merged into the `HiddenLayer` class to the `HiddenLayerApi` namespace:

```typescript
// v3.x
import type { ScanReport } from "@hiddenlayerai/hiddenlayer-sdk/resources/scans/results";

// v4.0.0
import type { HiddenLayerApi, ScanReport } from "@hiddenlayerai/hiddenlayer-sdk";
let report: HiddenLayerApi.ScanReportOfRecordV3; // the same type as ScanReport
```

The deep imports under `/resources/...`, `/core/...` and `/lib/...` are gone. Import from the package root, or from a resource subpath such as `@hiddenlayerai/hiddenlayer-sdk/scans`. `HiddenLayerClient` is the generated client without the scanners, credentials from the environment or beta warnings; use `HiddenLayer`.

## Client options

| v3.x | v4.0.0 |
|---|---|
| `bearerToken` | `token`, a string or a function returning one |
| `clientID` | `clientId` |
| `clientSecret` | `clientSecret` |
| `environment: 'prod-us' \| 'prod-eu'` | unchanged; `HiddenLayerEnvironment.ProdUs` or `.ProdEu`, or any URL, also works |
| `baseURL` | `baseUrl` |
| `timeout` (milliseconds) | `timeoutInSeconds` |
| `maxRetries` | unchanged |
| `defaultHeaders` | `headers` |
| `defaultQuery` | none; pass `queryParams` per request |
| `fetch` | unchanged |
| `fetchOptions` | none; wrap `fetch` |
| `logLevel`, `logger` | `logging: { level, logger }` |

```typescript
// v3.x
const client = new HiddenLayer({ clientID: "...", clientSecret: "...", environment: "prod-eu", timeout: 30_000 });

// v4.0.0
const client = new HiddenLayer({ clientId: "...", clientSecret: "...", environment: "prod-eu", timeoutInSeconds: 30 });
```

A `baseUrl` given in the options wins over `environment`. v3.x threw when both were set; v4.0.0 uses `baseUrl`. `HIDDENLAYER_BASE_URL` is used only when neither option is given.

`client.withOptions()` is removed: construct another client.

Requests send `User-Agent: @hiddenlayerai/hiddenlayer-sdk/4.0.0` (v3.x: `HiddenLayer/JS 3.x`); the `headers` option replaces it.

## Environment variables

| Variable | v4.0.0 |
|---|---|
| `HIDDENLAYER_TOKEN` | read, as in v3.x, unless `token`, or `clientId` and `clientSecret`, are passed |
| `HIDDENLAYER_CLIENT_ID`, `HIDDENLAYER_CLIENT_SECRET` | read, as in v3.x: exchanged at `/oauth2/token` for a token that is reused until 30 seconds before it expires |
| `HIDDENLAYER_BASE_URL` | read, as in v3.x, unless `environment` or `baseUrl` is passed |
| `HIDDENLAYER_LOG` | no longer read; pass `logging` |
| `HIDDENLAYER_CUSTOM_HEADERS` | no longer read; pass `headers` |

Credentials passed as options win over the environment: `token`, then `clientId` and `clientSecret`, then `HIDDENLAYER_TOKEN`, then `HIDDENLAYER_CLIENT_ID` and `HIDDENLAYER_CLIENT_SECRET`. v3.x let client credentials from either place override a token from either place.

A client with no credentials at all can still be constructed, but its requests fail with a `HiddenLayerError` naming the options and variables to set, where v3.x sent them with no `Authorization` header. Pass `auth: false` for that.

## Path parameters move into the request object

Every method takes one request object. Path parameters, which v3.x took as leading positional arguments, are now fields of it, named as in the API (snake_case):

```typescript
// v3.x
await client.sensors.retrieve(sensorId);
await client.sensors.update(sensorId, { plaintext_name: "..." });
await client.scans.results.listFiles(scanId, { page_size: 100 });

// v4.0.0
await client.sensors.retrieve({ sensor_id: sensorId });
await client.sensors.update({ sensor_id: sensorId, plaintext_name: "..." });
await client.scans.results.listFiles({ scan_id: scanId, page_size: 100 });
```

Body and query fields keep their API names, as in v3.x.

## Methods and types

Every method v3.6.0 had is on the same path in v4.0.0. The table lists each one's arguments, request type and response type in both versions. v3.x response types were named after the method; v4.0.0 types are named after the specification's schemas, under `HiddenLayerApi`.

|---|---|---|
| `models.retrieve` | `(modelID)` → `ModelRetrieveResponse` | `RetrieveModelsRequest` → `SensorSorModel` |
| `models.delete` | `(modelID)` → `void` | `DeleteModelsRequest` → `void` |
| `models.cards.list` | `(params)` → `CardListResponsesOffsetPage` | `models.ListCardsRequest` → `Page<ModelCardV4>` |
| `evaluations.redTeam.create` | `(params)` → `RedTeamCreateResponse` | `evaluations.ClientRedTeamBody` → `StartWorkflowResponse` |

| `evaluations.redTeam.retrieveStatus` | `(workflowID)` → `RedTeamRetrieveStatusResponse` | `evaluations.RetrieveStatusRedTeamRequest` → `WorkflowStatusResponse` |
| `evaluations.redTeam.submitTargetResponse` | `(workflowID, params)` → `RedTeamSubmitTargetResponseResponse` | `evaluations.SubmitTargetResponseBody` → `SubmitTargetResponseResult` |

| `runtime.evaluateResponse` | `(params)` → `RuntimeEvaluateResponseResponse` | `EvaluateResponseRuntimeRequest` → `ProviderPayload` |
| `sensors.create` | `(params)` → `SensorCreateResponse` | `SensorSorItemCreateRequest` → `SensorSorItemResponse` |

| `scans.upload.file.complete` | `(fileID, { scan_id })` → `FileCompleteResponse` | `scans.upload.CompleteFileRequest`, with `file_id` and `scan_id` → `CompleteFileResponse` |

## Pagination

Paginated methods return a `Page`. `for await` iterates every item across pages, as in v3.x. The items of the current page are `page.data` (v3.x: `page.items` or `page.getPaginatedItems()`); `page.hasNextPage()` and `await page.getNextPage()` move through pages, and `getNextPage()` updates the page in place.

Two methods change shape on purpose. In v3.x they returned the raw response envelope; in v4.0.0 they return a `Page` of its items:

| Method | v3.x | v4.0.0 |
|---|---|---|
| `scans.jobs.list` (`GET /scan/v3/results`) | `{ items, total, ... }` | `Page<ScanReportOfRecordV3Summary>`; the envelope is `page.response` |
| `sensors.query` (`POST /api/v2/sensors/query`) | `{ results, total_count, ... }` | `Page<SensorSorItemResponse>`; the envelope is `page.response` |

```typescript
// v3.x
const { results, total_count } = await client.sensors.query({ filter: { active: true } });

// v4.0.0
for await (const sensor of await client.sensors.query({ filter: { active: true } })) {
    console.log(sensor.sensor_id);
}
```

## Errors

| v3.x | v4.0.0 |
|---|---|
| `HiddenLayerError` (base) | `HiddenLayerError` (base, with `statusCode`, `body` and `rawResponse`) |
| `APIError`, `.status` | `HiddenLayerError`, `.statusCode` |
| `BadRequestError`, `AuthenticationError`, `PermissionDeniedError`, `NotFoundError`, `ConflictError`, `UnprocessableEntityError`, `RateLimitError`, `InternalServerError` | `HiddenLayerApi.BadRequestError`, `UnauthorizedError`, `ForbiddenError`, `NotFoundError` and the other errors the specification declares, each a `HiddenLayerError`; an undeclared status is a plain `HiddenLayerError` |
| `APIConnectionTimeoutError` | `HiddenLayerTimeoutError` |
| `APIConnectionError`, `APIUserAbortError` | `HiddenLayerError` with no `statusCode` |

```typescript
// v3.x
if (err instanceof APIError && err.status === 404) { ... }

// v4.0.0
if (err instanceof HiddenLayerError && err.statusCode === 404) { ... }
```

## Raw responses

```typescript
// v3.x
const { data, response } = await client.sensors.retrieve(id).withResponse();

// v4.0.0
const { data, rawResponse } = await client.sensors.retrieve({ sensor_id: id }).withRawResponse();
```

`.asResponse()` is removed. `client.fetch(path, init)` sends a request to any path with the client's credentials, retries and base URL.

## Model and community scanners

`client.modelScanner` (`scanFile`, `scanFolder`, `scanS3Model`, `scanAzureBlobModel`, `scanHuggingFaceModel`) and `client.communityScanner.communityScan` keep their options and behaviour. What changes:

- They return `ScanReport`, now `HiddenLayerApi.ScanReportOfRecordV3`, the same fields as v3.6.0's `ScanReport`.
- `requestSource` takes `HiddenLayerApi.ScanJobRequestSource`, the same strings plus `"AI Asset Discovery"`.
- `scanAzureBlobModel`'s `credential` is typed: a `StorageSharedKeyCredential`, `AnonymousCredential` or `TokenCredential` (v3.x: `any`).
- `scanHuggingFaceModel` rejects a repository file whose path would land outside `localDir`, and removes the temporary directory it created when a download fails.
- `getScanResults(client, scanId)` and `waitForScanResults(client, scanId)` take a `HiddenLayer` or `HiddenLayerClient`.
- `@aws-sdk/client-s3`, `@azure/storage-blob` and `@huggingface/hub` stay peer dependencies, at the same ranges, but are loaded only by the scan that needs one. Importing the package no longer fails when one is missing; that scan fails with an error naming the package to install.

## Beta warnings

Calling a beta endpoint still logs one `console.warn` per endpoint per process. The warning names the endpoint by HTTP method and path rather than by method name:

```
[BETA] POST /evaluations/v1/red-team: This endpoint is not GA or Production ready and is subject to changes at any time. Breaking changes may occur.
```

`warnBeta(name)` stays. `checkBetaEndpoint(path, method?)` takes the HTTP method as an optional second argument.

## Removed

- `toFile` and `Uploadable`: the API has no file-upload parameters; the model scanner uploads files itself.
- `APIPromise` and `PagePromise`: methods return `HttpResponsePromise` and `Promise<Page>`.
- `client.withOptions()`, `defaultQuery`, `fetchOptions`, `HIDDENLAYER_LOG` and `HIDDENLAYER_CUSTOM_HEADERS`, covered above.

## New APIs

v4.0.0 covers every public operation in the specification, 177 in all, against 29 in v3.6.0, including access (API keys, permissions, tokens, users), asset inventory, audit, compliance, governance, integrations, metrics, MITRE ATLAS, model intelligence, prompt sets, scan indices, SSO integrations and supply chain. [reference.md](../reference.md) lists each method.

## Migration checklist

- [ ] Rename `bearerToken`, `clientID` and `baseURL` to `token`, `clientId` and `baseUrl`; convert `timeout` to `timeoutInSeconds`.
- [ ] Move path parameters into each call's request object.
- [ ] Replace types imported from `/resources/...` with `HiddenLayerApi.*`.
- [ ] Iterate `scans.jobs.list` and `sensors.query` as pages, or read `page.response`.
- [ ] Replace `APIError` and its subclasses with `HiddenLayerError` and `statusCode`.
- [ ] Replace `.withResponse()` with `.withRawResponse()`.
